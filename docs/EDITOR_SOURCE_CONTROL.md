# Editor Git provider

The current preview embeds a Git panel in Developer Tools with local status and Refresh. Repository writes and remote operations are disabled.

Open **Tools → Options → DLUMA**, choose **Open Git**, then close Options to use the panel. The legacy **Source control enabled** setting should remain off.

Git for Windows must be installed. The panel finds `git.exe` on the executable search path or lets the user choose it. Each panel belongs to one project; it operates only when that project folder is the repository root. Linked Git worktrees are supported. Opening a project inside another repository does not implicitly authorize changes to its parent repository.

The backend also implements explicit initialization and remote setup, selected-file staging and unstaging, staged-file review, commits, branch selection and creation, initial branch publication, fetch, pull, push, history and cloning. These capabilities extend beyond the current preview's active functions. Every mutation requires a native project/generation lease that prevents retirement during the operation. Initialization never happens automatically. Commits include the reviewed index, including files staged outside the panel, and do not automatically stage other files. Publishing an unpublished branch explicitly selects a remote and creates its upstream; later Push uses that upstream. Clone refuses an existing destination or a checkout folder inside the open project. A failed clone may leave a partial checkout; existing user files are never replaced by the provider.

Branch switching and pull additionally require an Editor document lease. The host must save or close affected documents and prevent project or document changes until the operation finishes. These actions remain disabled without that integration. The Git backend also refuses dirty or conflicted worktrees. Pull permits fast-forward updates only. Push uses the current branch's explicit upstream without forcing updates. The provider does not reset, clean, stash or discard work automatically.

Git handles authentication through the user's normal credential helper or SSH setup. The panel stores no tokens or passwords, rejects credentials embedded in clone URLs and performs no remote operation on startup. Terminal prompts are disabled so an unavailable terminal cannot stall an operation. Configure authentication using [Git's credential helpers](https://git-scm.com/docs/gitcredentials) or the normal SSH tools before retrying an authentication failure.

Commands run asynchronously with individually escaped arguments, bounded output and cancellation. Each child starts suspended and resumes after the native host acknowledges its identity and ownership. Canceling an operation may occur after Git has changed local or remote state; refresh before retrying. If a child process cannot be stopped, further operations on that repository are blocked until it has been checked and the Editor restarted.

## Native startup integration

The stock **Source control enabled** option selects the built-in Perforce provider. Git uses the project-owned backend and requires the native Git settings, startup and panel integration. The current settings adapter saves the Git selection separately. If legacy source control is enabled, it records that prior value and asks the user to turn it off in Misc, save Editor settings, and restart. It does not rewrite the native preferences or automatically re-enable Perforce. Automatic migration remains part of the host integration work.

The Editor loads its preferences after DLUMA's host startup and before creating the legacy provider. A one-time option change during host startup can be overwritten by that load. Normal Options saves serialize the current option value, so a temporary override can also become a saved preference. Restoring an old snapshot at shutdown would discard later native edits.

The bridge owns three aligned dispatch pointers: the native provider getter and initializer, and the Editor initializer. It hides native provider exposure and retires only the exact fresh factory-owned object through its native destructor. It observes the Editor initializer's normal return for both legacy preference paths. An already-connected provider requires a restart rather than an in-place replacement.

`dluma_editor_source_control_start_early(callbacks)` accepts version1 size-checked callbacks and returns success after all expected-pointer transactions complete. A failure requires the host to decline protected startup before entering the legacy factory. `options_loaded` reports a matched legacy-enabled factory boundary. `init_attempt_completed` reports a matched normal return from the Editor initializer, including when legacy source control is disabled. The owner-thread-only `native_snapshot` refreshes the current flag and exposes `boundary_seen` and `init_returned` separately. Normal return does not certify preference parsing or completed frame setup. The bridge never writes preferences. Saving belongs to the options policy after the native working copy has retired and the save path is ready.

Guard code and minimal late-callback state remain process-pinned. `stop` disables borrowed policy notifications and waits for their drain; it does not authorize unloading a callback address that another thread may have fetched. Partial installation rollback preserves foreign pointers and retains unresolved ownership/protection state. The native caller, policy and package must be qualified together before this integration is activated.

The Git panel uses the existing authenticated single-view companion host. Its launch includes the standard panel arguments plus an admitted absolute `--project-root` and nonzero `--project-generation`. Git starts only after successful panel binding. The native host must verify and lease that project generation for each mutation, then retire the panel and pipe when the generation ends. The additional document lease must use the same identity and lifetime; an unconditional permission callback is not a valid adapter.

The companion shares the existing theme generator and pinned desktop runtime. For an isolated build using already-generated theme files, pass `-p:DlumaSkipEditorThemeGeneration=true`. Full builds generate those files normally. No Git runtime or credential manager is bundled.
